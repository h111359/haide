| Area | Solution architect | Software developer |
| --- | --- | --- |

I propose these concrete changes:

1. **Split the architect’s workflow** into assessment, technical decision resolution, and implementation-plan preparation. Add a technical assessment convention covering evidence, edge cases, risks, knowledge effects, and readiness.
2. **Extend the existing implementation-plan convention** into the execution brief. Include scope, authority, settled decisions, assumptions, exact targets, ordered tasks, dependencies, acceptance criteria, documentation work, and verification methods. Keep `plan.md` as the single current execution document.
3. **Split the developer’s workflow** into input validation, implementation, and verification/handoff. Add an evidence contract covering task results, changed paths, checks, deviations, protected-resource inspection, and pending dependencies.
4. **Reuse Business analyst contracts** for requirements readiness, clarification history, context reading, and framework protection. Keep Activity writes with the host/runtime and managed specification writes with Specification-manager.
5. **Add focused validators and behavioral scenarios.** Structural validation alone cannot demonstrate that an agent respects scope, handles unanswered decisions, or withholds success after failed checks.

- Require questions for decisions reserved to the user; retain autonomy for technical choices already delegated.
- Record material issues encountered without turning every task into an exhaustive audit.
- Require proportionate verification rather than new tests for every document edit.
- Allow assessments as supporting evidence, while keeping execution scope in the plan.
- Preserve HAI’s permitted archival supplements and chronicle synchronization.
- Use staged knowledge replacement rather than a destructive delete-then-insert sequence.
- Treat context-registry `Update` metadata as nonauthoritative until a write contract exists.
