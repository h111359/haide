# HAI 0.3.0 candidate

This experimental candidate replaces built-in instruction agents with a Python
runtime and separates optional workspace extensions from the reusable bundle.
The human selected 0.3.0 for release preparation. Source metadata is prepared;
exact source and ZIP verification are recorded separately. Publication is pending.

## Changes and breaking behavior

- `.hai/start.md` directs the host to the Python 3.11+ runtime at
  `.hai/tools/hai.py`. Environment, Activity, profile, package, recording-schedule
  and host-capability operations have documented JSON inputs and results.
  Mutations preview by default; applying changes requires explicit `--apply`
  and provenance. Partial results and unresolved dependencies remain visible.
- Built-in coordinator, environment, Activity and domain agent packages are
  removed from `.hai/`. Core startup and administration require no optional
  agent, model profile or source library. Hosts retain task coordination.
  Existing callers that depend on the removed packages must use the runtime or
  separately installed extensions.
- Optional agents are complete packages installed under `.hai_env/agents/`
  and registered separately. Runtime package operations validate source,
  replacement differences and registration. Golden packages in this
  repository's `hai_agents_library/` are separate source material, excluded
  from this bundle; installing the core does not install those extensions.
- Every agent declares a package-owned configuration contract. Saved overrides
  live outside packages at `.hai_env/config/agents/<name>.json`; absent values
  use declared defaults. Invalid settings do not silently become defaults.
  Existing optional definitions require compatible contracts before use.
- State format 3 extracts specification settings into Specification-manager's
  configuration file. Activity location and chronicles remain central. Shared
  Activity and recording-evidence contracts distinguish lifecycle, actual work,
  exact transcripts and operation-specific recording proof.

## Compatibility and upgrade

| Boundary | Candidate target |
| --- | --- |
| Bundle | `0.3.0` |
| Current environment state format | `3` |
| Recognized environment state formats | `[2, 3]` |
| Agent configuration contracts | Formats `1` and `2`, as declared by each package |

The [published manifest](https://github.com/h111359/haide/blob/f35b69b7f16d29b06bbfdc66c0022a306087ad90/.hai/release-0.3.0.json) snapshots the owning
[state declaration](../.hai/contracts/state.json). Format 2 is read-only migration
context and returns `migration_required`; it is not a fully operational format-3
environment. Bundle, state and agent configuration versions are independent.
The agreed experimental `0.x` policy calls for a MINOR increase for these new
capabilities and breaking changes; a PATCH increase would understate their impact.

Before replacing `.hai/`, preserve `.hai_env/`, external configuration, Activity
records, transcripts, specifications and product files. Do not overlay the new
tree onto old built-in agent directories and assume those retired packages are
still supported. Replace the reusable tree as a whole after preserving local
modifications. Keep the license and required documentation with the distribution.

Format-2 consumers need an explicitly authorized specification extraction using
the runtime's `environment migrate-specification` operation after reviewing the
preview, installed owner contract, destination conflicts and backup safeguards.
It requires a registered compatible Specification-manager, including when the old
specification feature was disabled. Format-1 consumers need an owner-reviewed,
explicitly authorized ordered migration; this release does not provide an
automatic format-1 conversion. Never upgrade by changing only a version marker.
Existing legacy Git settings need the separately installed Git-manager's explicit
extraction procedure. See the [configuration migration guide](agent-configuration-migration.md),
[historical Activity migration boundaries](activity-migration.md) and
[installation instructions](../INSTALL.md).

The core bundle does not declare or migrate a specification-tree compatibility
target. Specification content and compatibility remain the optional owner's
responsibility. A manifest records shipped contracts, not consumer migration.

## Validation and remaining work

Core checks on Linux with Python 3.12.3 ran 176 tests: 174 passed and two
Windows-only checks were skipped. This includes startup/migration, agent format,
configuration, Activity/recording and runtime workflow suites. The installed
workspace audit passed for ten registered extensions; those local extensions are
excluded from the core bundle. Windows and macOS execution remain unverified.

The intended package is `hai-0.3.0.zip`, containing `.hai/`, the MIT license and
required same-commit documentation. It excludes `.hai_env/`, the optional source
library, Git data, saved settings, profiles, Activities, transcripts and secrets.
Exact-commit export, archive inspection, digest and downloadable publication
verification must follow the release-source commit. These notes do not claim
those pending results or authorize a commit, tag, push or publication.
