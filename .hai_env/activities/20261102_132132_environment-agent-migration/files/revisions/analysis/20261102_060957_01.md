## Scope and assumption

Assess merging `.hai/agents/activity-manager` into `.hai/agents/environment-manager`, leaving Environment-manager as the sole role for those responsibilities. Leader remains. Removing Leader would require a larger redesign. No merge or implementation was authorized.

## Findings

The merger is feasible. Its main disadvantages are:

- Broader scope and longer instructions: Environment-manager's administration responsibilities would combine with Activity-manager's general clarification, analysis, planning, implementation and verification execution.
- A model tradeoff: Activity-manager uses advanced/high and Environment-manager uses light/high. A merged role with one declared model profile must choose a compromise or require an explicit redesign of model selection. Runtime quality and cost were not measured.
- More opportunities to confuse configuration permission with permission to move Activity records or perform historical transcript backfill. These remain separate authorizations even inside one role.
- More complicated prerequisites: bootstrap/setup exceptions for establishing an environment must remain distinct from the Activity context required for substantive work.
- Coordinated migration work: routing and references across Leader, shared conventions, and installed/source Git-manager packages would need review and updates.

Benefits include fewer role identities and fewer handoffs. Concurrency loss is not inherent: the sole-writer requirement applies per Activity and still governs merged-role execution. The current role split is not a security sandbox.

## Recommendation

Keep the roles separate given Activity-manager's broad execution scope. If merged, retain distinct procedure groups, explicit authorization boundaries, and appropriate prerequisite checks within the resulting role.
