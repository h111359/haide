## Prompt:

This rule should serve not only development of HAI agents, but should be valid when HAI is used for other purposes, like software development or execution of flows or whatever it is used for. So don't limit yourself only with agents development.


## Outcome:

Agreed. The principle should govern **all HAI work**, regardless of task type.

The general rule should be:

> **Artifact ownership and placement.** Before creating an artifact, the host or assigned agent MUST identify its purpose, owner, intended lifetime, and canonical destination. Requested deliverables and reusable resources MUST go to their established product, project, or operational locations. Task-specific working material and execution evidence MUST remain with the owning Activity or invocation unless the user or an applicable contract explicitly designates another destination.

This covers software changes, documents, flow execution, research, configuration, and agent development.

The distinction is based on purpose:

- **Deliverables:** software, requested reports, deployed configuration, reusable flow definitions, tests, templates, and maintained documentation.
- **Working material and evidence:** scratch scripts, intermediate drafts, implementation assessments, test-run results, review notes, and execution traces.

A report or execution log can itself be a requested deliverable. Its format or filename does not determine its placement.

HAI should apply this through shared conventions and startup instructions, with three checks:

1. **Planning:** assign each artifact a purpose, owner, lifetime, and destination.
2. **Execution:** classify newly discovered artifacts before creating them.
3. **Completion or publication:** inspect the actual files and exclude misplaced working material from delivered or installed content.

Specialist definitions should reference this shared rule. Existing project storage contracts should remain authoritative, and existing files should never be relocated automatically.
