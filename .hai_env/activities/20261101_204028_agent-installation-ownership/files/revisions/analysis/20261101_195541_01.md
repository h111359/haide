# Agent source and installation layout

Recorded 2026-11-01T19:23:44Z from Leader's returned read-only specialist review. These are proposals; the user has not selected an option.

## Current arrangement

Three core roles are maintained directly in `.hai/agents/`. Four optional reusable agents have canonical sources in `hai_agents_library/agents/` and installed snapshots in `.hai_env/agents/`. Advisor exists only in the workspace.

The distinction is intentional today, but it gives reusable agents two different development workflows. The authoritative descriptions are `.hai/conventions/framework-layout_conv.md` and `hai_agents_library/README.md`.

## Options

| Option | Main idea | Tradeoff |
| --- | --- | --- |
| 1. One source library | Put all reusable agent sources in the library, with a manifest identifying required core and optional agents. Keep the two existing runtime locations initially. | Consistent development and packaging with a smaller migration. |
| 2. One source library and one runtime location | Keep all reusable sources in the library; install all runtime agents under `.hai_env/agents/`. Keep `.hai/` for shared framework and bootstrap. | Cleaner long-term layout, but bootstrap must install mandatory roles before environment initialization without circular dependencies. |
| 3. Maintain everything directly in `.hai/agents/` | Remove the source/snapshot distinction. | Simpler folders, but development and runtime become coupled. |

## Recommendation

Start with option 1. It resolves inconsistent source ownership while preserving current runtime behavior. Consider option 2 as a separate later phase if one runtime location is also desired.

Library membership must not grant execution permission: runtime catalogues remain the registration authority. Workspace-only agents stay local unless explicitly promoted into reusable packages.
