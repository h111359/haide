# Skill metadata and portable invocation

Packages follow the [published Agent Skills specification](https://agentskills.io/specification), verified 2026-09-22. `SKILL.md` frontmatter contains `name`, `description`, `compatibility`, and string-valued `metadata`. The `metadata.aih` string encodes JSON matching `schemas.json#skill_metadata`. JSON frontmatter is valid YAML and permits a strict standard-library decoder; package discovery also accepts the documented simple scalar YAML form.

Each extension declares stable ID/name/version/purpose, capabilities and exclusions, input/output contracts, standalone parameters, possible effects/write scope, prerequisites/authorization, dependencies, compatibility, bundle version and default enablement. Metadata is descriptive, not an authority grant. The seven core packages default enabled; optional Git defaults disabled. Installed, enabled, available and authorized are separate states.

`catalog.yaml` and `README.md` are generated from package metadata by `engine/build_skills.py` during build/explicit maintenance only. Entries include package location, frontmatter hash, bundled-resource manifest hash, and exact bundle versions. Discovery reads metadata, fingerprints and manifests without returning bodies or executing code. Report malformed, duplicate, incompatible, disabled, missing and stale packages; ambiguity/integrity failure blocks execution. New valid metadata can appear in read-only inventory, but reconciliation requires maintenance with no request/owner.

Shared authoring conventions live here. Released packages contain generated required references, schemas and verbatim Python helpers with a manifest. The installed core is immutable during product work. Standalone usage needs only a copied package, Python 3.11+, declared intrinsic tools, and an explicit invocation contract; no AIH engine, portal, database or fixed product-state path.

The compact invocation records: instruction/source reference; skill and invocation ID; explicit canonical named root list/access; workspace revision; root-qualified input/output locations; action scope and intended effects; host constraints; and applicable authority. Implementation additionally binds a plan and approved-plan fingerprint, or explicit direct implementation authority with an internally generated persisted plan. Requirements/setup/documentation/read-only invocations do not acquire implementation-plan requirements merely to write their permitted output records. Validate consequential authority before side effects. Persist effective contract and result/evidence references; record the host's actual assurance without claiming independent user identity verification.

Bundled helpers must perform inventory, extraction, sensitive screening, schema validation, question parsing/export/review, amendment revision capture, plan validation, record writing and evidence fingerprints. Semantic tasks remain the agent's responsibility. Never imitate a missing helper through ad hoc state edits. Standalone records do not recreate framework lifecycle or grant another skill installation requirement. Direct implementation includes local planning guidance. Test diagnosis cannot authorize unrelated fixes. Read-only questions write only question-owned answers/evidence, not product docs.
