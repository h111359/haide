# Execution, tests and evidence

A plan binds requirements-definition, workspace and relevant content/instruction revisions. Every sequential task has stable ID, sequence, intended outcome, requirement/decision links, exact root-qualified affected paths including new paths, action types, dependencies and completion evidence. Unknown target paths require bounded investigation then a revised plan before dependent writes. Required task purposes include changed-behavior test authoring, full required suite execution, authorized repairs/reruns, documentation application, documentation verification and results recording. Direct implementation persists this plan before changes without inventing human approval.

One action owns the installation globally across starting/running/stopping/uncertain/external-reserved states. Stop is the only operational command while busy; passive status/help/navigation/download are available. No queued replacement commands. Sequential implementation acknowledges safe boundaries with checkpoints; an interrupted task remains incomplete. A blocked request with no owner is idle, still open, and eligible for independent Q&A. A manual handoff persists reservation until explicit Stop/release confirms external termination and reconciles evidence. Returned text cannot bypass it.

Each registered suite declares stable ID, environment/runtime/prerequisites, root-qualified working/source/output/cache/temp paths, workspace revision, required access, expected filesystem/network/service effects, isolation, cleanup, timeout and current authorization. Fail closed if the configured runner cannot contain all effects. No fallback environment or skipped required suite implies success. Required test inventory includes maintained relevant regression tests across roots. Record final-content/instruction/workspace fingerprints, command identity, start/end, exit code, status, sanitized full output reference and concise failures. Process exit and task correctness are separate results.

Default repair budget is three unsuccessful cycles per stable unresolved failure. Each cycle preserves diagnosis, authorized repair, rerun evidence, duration and actual token usage when available. Optional elapsed/token limits and no-progress detection may stop earlier. Restarts/new segments/cosmetic failure names do not reset counts. Explicit human extension records reason/scope and preserves all attempts; it never waives tests. Unrelated defects require include/defer/investigate disposition. A deferred defect failing a required test continues blocking successful completion. No weakening tests solely to pass.

Each implementation run/segment creates `implementation_log.jsonl` and `implementation_summary.md` before product changes. Log append records event sequence/time, run/segment/task, phase, root-qualified scope, attempted/finished changes, checks, evidence refs, blockers, repair count, checkpoint and outcome. The summary distinguishes planned/applied/verified/retained incomplete changes, required suite statuses, documentation increment status, unknowns and next safe action. Available full sanitized evidence stays inspectable even when a compact view omits detail. Missing token telemetry is null/unavailable, not zero.

Ready to close means completion gates pass against current content and documentation; it is not closed. Explicit human Close successfully revalidates approval/scope, sequential task completion, all required tests, resolved blockers and reconciled documentation, then archives. Cancelled/rejected closure preserves evidence, unverified changes and a current-state notice without requiring passing tests. No auto-commit, push, merge, deploy or publication is implied.
