## Prompt:

Open new activity and let's discuss the agents in .hai folder. It is strange now that some agents are in this folder and some are in hai_agents_library. Do you have some proposals how to resolve this inconsistency?


## Outcome:

Opened a new Activity: **Discuss agent source and installation layout**.

The current structure mixes two distinctions:

- **Required versus optional:** core agents live in `.hai/agents`.
- **Source versus installed copy:** reusable optional agents live in `hai_agents_library/agents`, with installed copies in `.hai_env/agents`.

That explains the split, but it makes the organization harder to understand.

I see three options:

| Option | Main idea | Tradeoff |
|---|---|---|
| **1. One source library** | Put every reusable agent’s source in `hai_agents_library/agents`, including the three core agents. | Consistent development and updates, but two installed locations remain. |
| **2. One source library and one installation folder** | All reusable sources in the library; all installed agents in `.hai_env/agents`. | Clearest structure, but startup must install the required agents before environment initialization. |
| **3. Everything directly in `.hai/agents`** | Remove the separate source-library model. | Simple folders, but editing an agent immediately changes the running installation. |

**I recommend option 1 as the first step, with option 2 as a possible final structure.**

The guiding principle would be: **“core” describes which agents are required, rather than how their source is maintained.** A small bundle manifest would identify required agents; optional agents would use the same package format and installation process.

Workspace-specific agents such as Advisor could remain local without needing a library counterpart.

The proposals are recorded in the [new Activity’s analysis](/home/hromar/Desktop/repos/haide/.hai_env/activities/00000000_000000_active/analysis.md). No framework changes have been made.
