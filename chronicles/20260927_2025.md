## Prompt:

And how this will happen? How the registration of a new folder will happen and all these parameters - fulfilled?


## Outcome:

Under the updated requirements, **registering a folder and documenting it are two separate steps**. Saving the folder settings does not automatically start an agent.

A typical flow would be:

1. **Finish or cancel any open request.** No operation may be active.
2. **Open Settings → Workspace → Add folder.** Select the folder and provide its name, purpose, and intended access: read-only or writable.
3. **Validate and save.** AIH checks the location, host permissions, and whether it overlaps or conflicts with another registered folder. It saves the registration without moving files.
4. **Explicitly start the required documentation review.** AIH inventories the folder, examines its contents, updates the central product documentation, and reviews dependencies and required test coverage.
5. **Start the next request once the review is complete.** If something prevents completion, AIH shows the blocker.

The fields in 2.5.1 come from different places:

| Field | How it is supplied |
|---|---|
| Fixed framework home | Established during installation/setup. |
| Stable folder identifier | Assigned by AIH when registered and retained afterward. |
| Name and purpose | Supplied by the human. |
| Resolved filesystem path | Derived and validated from the selected location. |
| Read-only or writable access | Selected by the human, subject to host permissions. |
| Availability | Checked by AIH: does the folder exist and can it be accessed? |
| Documentation baseline status | Determined by the documentation review. Initially incomplete for a new folder. |
| Pending review status | Recorded by AIH when documentation, dependencies, or test coverage need review. |

**These are the intended responsibilities, but the requirements do not yet specify every interaction**, such as the exact form fields or the name and placement of the action that starts the review. The flow above is a concrete interpretation of the current rules, not a claim that it is already implemented.
