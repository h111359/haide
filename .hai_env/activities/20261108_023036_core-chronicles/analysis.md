# Core chronicles integration results

## Final architecture

Chronicles are now core functionality in .hai/, not an optional registered agent. The source reader and its tests live in .hai/tools/chronicles; recording contracts/concepts/procedures live in the corresponding shared core locations. Runtime recording synchronize/verify provide real persistence/readback. Startup instructs host to provide explicit Activity/source/range/enablement provenance, schedule cadence batches and synchronously flush before closure. Core never discovers unrelated sessions or starts a background recorder.

The installed and source-library codex-chronicle-manager packages were retired from live paths and its registration removed. Exact original package trees and file hashes remain in files/retired-chronicle-manager; installed/source originals were identical. External settings were preserved. Core works without optional agent registration/profiles. Git-manager's installed and golden procedure references now use core verification, preserving role/host boundaries. No generic agent was recreated inside .hai/.

Enabled or independently mandatory closure cannot use pending/unavailable plus mandatory:false to skip recording. It synchronizes assigned source, verifies exact artifacts, then finalizes the live cutoff and archives. Disabled/no-obligation operations create no transcript/checkpoint. Existing explicit proof interface remains supported with strict gate/path/hash checks. Current source bounds and source-prefix fingerprints protect history; exact text, duplicate idempotence, source intervals and cross-Activity overlap checks prevent mixing assignments. A closed ledger's fixed cutoff remains verifiable after future workspace enablement changes.

Enablement toggles increment a preserved internal revision. After a transition, explicit attributable intervals for all registered sources must retain every already recorded exchange, including valid last records without trailing newline. Cadence-only changes do not reset coverage. Missing sources, malformed/edited artifacts, unknown legacy state or pending/prepared checkpoint work block rather than fabricate or overwrite evidence. New explicit synchronization can resume an interrupted active closure's retained live binding; closed cutoffs remain fixed.
