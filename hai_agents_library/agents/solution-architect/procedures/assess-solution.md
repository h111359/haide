# Assess solution

## Description

Research the current technical request and prepare an attributable assessment with readiness evidence.

## Inputs

| Input | Meaning | Requirement | Source | If absent |
| --- | --- | --- | --- | --- |
| [input:workspace_root] | Explicit validated workspace root. | Mandatory | Host coordinator. | Retrieve before dependent work. |
| [input:instructions] | Fixed and applicable workspace/session instructions. | Mandatory | Caller and readable fixed instructions. | Empty readable file is valid; missing instructions block dependent work. |
| [input:authority] | Actual human task, scope, constraints and permissions. | Mandatory | Human request relayed by host. | Retrieve existing authority; never invent permission. |
| [input:activity_context] | Validated core state, stable active Activity and relevant current records. | Mandatory | Host and runtime evidence. | Return missing dependency; no standalone bypass. |
| [input:work_context] | Current requirements, acceptance, evidence sources, attachments and decisions. | Mandatory | Host and authorized task sources. | Retrieve facts; return unresolved necessary decisions. |

## Prerequisites

Validated selected configuration, mandatory instructions, compatible environment, stable active Activity and meaningful authorized assignment. Current business-readiness evidence is available before dependent technical planning.

## Rules

None.

## Steps

1. Establish [input:workspace_root], [input:instructions], [input:authority] and [input:activity_context]; retrieve authorized missing context and stop dependent work on unresolved prerequisites.

2. Compare [input:work_context] with the current input and decision evidence. Identify affected people, intent, boundaries, constraints and measurable acceptance; consume all applicable business-readiness checks, not an assumed prior pass.

3. Inventory supplied and nested attachments, designated context and relevant project conventions. Read authorized readable materials completely, distinguish placeholders, and identify nontext/unreadable limits. Follow the registry contract for supplemental sources; registry Prompt/Update metadata grants no execution or write authority.

4. Inspect relevant implementation, interfaces, data, existing patterns and operational constraints before asking for discoverable facts. Use authorized external research for real external factual gaps; separate findings from decisions. Record distinct material defects, inconsistencies, duplication, broken references and risks encountered without expanding repair scope.

5. Analyze feasible options, edge/empty/boundary conditions, first use and revision, migration/compatibility, failure and recovery behavior. Explain knowledge conflicts and how existing intent is preserved or explicitly changed. Identify knowledge deltas and required owners.

6. Prepare the ordered assessment sections and T1–T6 evidence under the technical assessment convention. Mark unresolved choices and dependent actions explicitly. If a consequential decision needs clarification, pass the assessment and choices to host for Resolve technical decisions as assessment and decisions.

7. Request host persistence with original input references and revision provenance. Use plan_contract.py for structural/readiness diagnostics after reading its README; correct authorized draft problems, but keep unresolved readiness blocked. Return actual evidence and checks; do not publish a false ready assessment.

## Outputs

| Output | Meaning | Completion criteria |
| --- | --- | --- |
| [output:work_result] | Proposed assessment, source identities, findings, decisions, readiness results and unresolved dependencies. | Actual results, evidence, current identity and unresolved dependencies are distinct; host persists canonical records. |
