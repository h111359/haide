# Standalone use and compact invocation

Copy this entire skill directory into an ordinary permitted workspace folder. No installed AIH engine, portal, database or fixed product-state directory is needed. Python 3.11+ is required; Git is additionally required only for the Git skill. Semantic work requires a hosting agent; helper execution alone does not interpret product meaning or prove agent compliance.

Start from [example-contract.json](../resources/example-contract.json). Replace its canonical absolute fixture path, initiating instruction and root-qualified inputs/outputs with the actual supplied locations. Root IDs must be unique, disjoint and stable. List read-only references separately and declare all intended writable scopes/effects. Keep results in an explicitly allowed writable directory. Contract intake authorizes reading the named contract only, not arbitrary files beside it. Host constraints can narrow but never widen these declarations.

The schema is [schemas.json](../resources/schemas.json), record `standalone_invocation`. Required fields are schema_version, invocation id, skill id, initiating instruction, workspace roots and revision, input references, output directory reference, permitted scope, effects, authorization mode/instruction reference and constraints. For approved implementation add the exact plan reference and approved plan fingerprint; for direct mode record explicit direct-implementation authority, then generate/persist the plan before changes. Setup/requirements/docs/Q&A authority does not require an implementation plan merely to write its permitted records. Incompatible/missing consequential authority blocks before writes.

```sh
python -B /path/to/copied-skill/scripts/helper.py integrity
python -B /path/to/copied-skill/scripts/helper.py validate --contract /path/to/invocation.json
python -B /path/to/copied-skill/scripts/helper.py inventory --contract /path/to/invocation.json --artifact inventory.json
```

`--data` takes a JSON root-qualified reference, such as `' {"root":"product","path":"exchange-input.json"} '`, without the surrounding spaces. Input data is read only within declared roots. Supported operations: validate, inventory, extract, record, export-form, receive, review, amendment, validate-plan, validate-tree, apply-edits, reconcile, run-test, git and integrity. `--artifact` names an output below the invocation output location. Inventory/extract collect hashes and safe static facts without importing inspected code. Record writes screened JSON content. Schema/tree/plan validators reject missing consequential structure. The run-test/git helpers require Linux Landlock ABI 3+ and libseccomp; an unavailable backend blocks execution rather than running unconstrained. Declare an explicit `runtime` root-qualified ordinary writable directory, include it in scope, and add the exact `test-execution` or `git-status`/`git-diff`/`git-log`/`git-branch`/`git-commit`/`git-push` effect. Runtime output is separate from product state; each run uses a fresh uniquely owned directory. `run-test` accepts the documented typed Python unittest/script contract with explicit source/write paths, environment, isolation, prerequisites, cleanup=retain and instruction-bound authorization. `git` accepts `repository` (root-qualified) and action status/diff/log/branch/commit/push. Branch/commit/push additionally require the repository `.git` directory in explicit writable scope. Branch names are literal and non-destructive. Commit requires exact root-qualified paths, message, author_name and author_email; it records intent-to-add then commits only the selected files while preserving unrelated staged changes. Hooks, filters, external diff and global/system configuration are disabled. Push requires authorization.network=true, one exact branch, configured remote, and matching reviewed expected_url using HTTPS without embedded credentials; no force/delete/wildcard/mirror flags exist. Authentication uses only a named authorization_header_env reference or explicit TLS credential file references granted read-only. Network is disabled for every other Git action. Pull requests and SSH/custom transport use an explicitly independent user-operated tool boundary and never follow automatically. No remote effects are exercised by the delivered local tests. Complete sanitized process output and actual exit/termination evidence are returned; no global AIH state is created.

The exchange operations share the engine's canonical code bundled locally. Export data is `{request:{id,title,summary}, questions:[...], interpretation_revision:1}`. Questions use id/revision/question/explanation/why/instructions/respondent/kind/blocker/options/answer/selected. Receive data is `{text,current_request,forms,current_questions,review_revision}`; it stages proposals and keeps original content, never adopting answers. Review data is `{questions,receipt,decisions,revision}`; decisions name question_id and choice accept/edit/retain/unresolved, with explicit conflict resolution as needed. The result remains draft until the initiating semantic workflow explicitly submits it. Amendment data is `{identifier,text,previous,source,disposition}`; persist each returned revision under a unique revision filename. Review/refusal tests are in the framework validation suite; host applications should preserve expected-revision checks and immutable history when composing these primitives.

The implementation package also provides `apply-edits` and `reconcile` through the canonical product-edit journal engine. Both require skill=implement-plan, the implementation effect, current approved-plan/direct authority, and an already persisted complete `plan` reference. Input is `{task_id:"T1",edits:[{path:"product:src/file.txt",action:"create",expected_hash:null,content:"..."}]}`; modify/delete/move require the reviewed current SHA-256, and move names its exact approved destination. Effects must cover exactly the selected task. Earlier mutation tasks require completed retained journals; earlier nonmutation tasks need `previous_task_evidence:[{task_id,ref,sha256}]` referring to a completed outcome or an actual passing run-test result with that task ID. Required suites still need actual execution; journal completion alone proves effects, not acceptance.

Journals, captured plan/authority, per-root progress and readable summaries live under the declared output, with one OS-locked writer. No `.aih_product` directory is created. Current access and plan bindings govern every retry. `reconcile` input `{task_id:"T1",apply:false}` inspects partial outcomes; `apply:true` explicitly completes only the already recorded authorized effects. A copied destination is recognized before finishing a move. Later human edits, revoked access, changed plan/authority and changed root mappings block; no journal restores old permissions. `run-test` is also available directly from the implementation package when the additional test-execution/runtime/environment effects are explicitly authorized. A zero-test unittest collection is blocked.

## Outputs

Each successful helper operation writes the effective `invocation.json` and requested result/evidence artifact inside the specified output directory. References retain named root and workspace revision; inventory records fingerprints, extraction version and limitations. Usage unavailable is reported as unavailable. Write semantic deliverables with their source links through `record` or the hosting environment's equally confined validated editor. Do not claim that self-declared instruction references independently authenticate a human. POSIX helper writes use safe directory handles; Windows standalone mutation is blocked unless a tested compatible backend is supplied.

For realistic use, supply a small source directory and ask the agent to perform this skill's concrete task. Inspect its interpretation/plan/answer/documentation and evidence independently; package integrity or helper success alone does not establish behavioral portability.
