## Implementation

The runtime provides `activity chat-read` and `activity chat-post`, documented in
[the runtime guide](../../.hai/tools/runtime/README.md) and
[chat convention](../../.hai/conventions/activity-chat_conv.md).

- All assigned agents use the same stable Activity ID to read and append attributed
  coordination messages. Fixture tests cover different authors; the host posted
  and read back a real verification note in this Activity.
- Posts append through an append-only descriptor under the runtime lock. There
  is no edit/delete/clear action; canonical artifact replacement rejects the chat.
  Tests verify exact old-prefix preservation, unsafe targets, corrupt history,
  competing writers and retained partial failures.
- Chat remains readable and unchanged after archival; a new Activity starts with
  empty separate history. Posts reject closed or stale Activity IDs.

All 15 new chat tests passed. Core regression checks ran 191 tests: 189 passed,
with two Windows-only checks skipped on Linux/Python 3.12.3. Windows and macOS
execution remain unverified. Append-only behavior is enforced through supported
runtime operations; shared-user filesystem access is not an OS immutability
boundary. No optional agent was installed or invoked to simulate participation.

## Resolution

Completed with explicit user acceptance: “ok, complete the activity and commit,
open fresh activity”, following the implementation report and disclosed limits.

1. Shared agent access: runtime chat-read/chat-post target the same stable Activity
   ID; tests verify multiple author identities and the host verified a real post/read.
2. Posted-message preservation: applied posts append without replacing prior bytes;
   no edit/delete/clear endpoint exists and shared agent rules forbid direct
   modification. This is enforcement through supported runtime operations, not an
   OS permissions boundary against same-account filesystem access, as disclosed
   before acceptance. Failure and concurrency tests verify retained history.
3. Activity separation: archived chat remains readable with unchanged bytes;
   new Activities have empty independent histories and reject stale-ID posts.

Verification: 15 new chat tests passed; core checks ran 191 tests with 189 passed
and two Windows-only skips on Linux/Python 3.12.3. Windows/macOS execution is
unverified. The linked Activity contains test results and live readback evidence.
