# HAI 0.2.0 candidate

This candidate replaces optional Request tracking with mandatory Activities and
moves environment state to format 2. It is prepared for a source commit and local
packaging; it has not been published. HAI remains experimental.

## Changes and breaking behavior

- Every substantive HAI task belongs to an Activity, including brainstorming,
  analysis and specification work. Startup resumes current work; a new chat alone
  does not create or close an Activity. The framework role is `activity-manager`,
  replacing `request-manager`.
- Activities have stable identities, tracked steps, supporting artifacts, and an
  explicit lifecycle. Material revisions preserve history after implementation
  starts. Completion follows the agreed task scope and may be analysis alone.
- Activity storage is mandatory, configured by safe workspace-relative
  `activities.location`, default `.hai_env/activities`, without an enable switch.
  Closed records retain their identity under UTC closure timestamp folders; new
  substantive work belongs to a new linked Activity.
- Optional chronicles now belong to individual Activities. Exact source segments
  and attributable delayed synchronization preserve history; recording does not
  implicitly backfill periods when it was disabled. There is no global chronicles
  location in format 2.
- Durable product specifications remain independent. Their standalone use,
  structure, compatibility rules and product obligations are unchanged; finishing
  specification work does not require implementing the described product.

## Compatibility and migration

| Boundary | Candidate target |
| --- | --- |
| HAI bundle | `0.2.0` |
| Current environment state format | `2` |
| Supported environment state formats | `[2]` |
| Specification compatibility | `1` |

The [current manifest](../.hai/release-0.2.0.json) snapshots both owning
declarations. These independent targets do not assert that a consumer workspace or
specification has been migrated. A MINOR increment follows the agreed experimental
`0.x` policy for new capabilities and breaking changes; PATCH would understate
the required state and workflow migration.

Existing format-1 state and Request records require scoped owner assessment and
an explicitly authorized migration. Replace the reusable framework as a whole,
preserve local data, and do not convert records merely by changing their version
or folder names. The retired `compatible_version` field remains unsupported.
Specification contract 1 is retained because temporary-record terminology changes
preserve all specification obligations; no specification-marker rewrite is implied.
See [installation instructions](../INSTALL.md) and the detailed
[Activity migration boundaries](activity-migration.md).

## Validation and limits

The candidate was validated on Linux with Python 3.12.3: 141 tests
passed and 3 Windows-only tests were skipped (startup: 44 passes, 2 skips; agent
tools: 57 passes; specification: 40 passes, 1 skip). The registered-agent audit
found no issues across 9 agents, and local profiles validated. Independent review
confirmed specification contract 1 remains applicable. Windows and macOS execution
has not been established by these checks.

One explicitly authorized workspace migration verified format-2 configuration
preservation and relocation of all 37 historical transcript files with matching
hashes. This is evidence for that scoped migration, not a general automatic
upgrade guarantee. Validation helpers establish their documented mechanical
checks, not semantic correctness, product implementation or migration approval.

The candidate ZIP will contain reusable `.hai/`, the MIT license and required
documentation. It excludes `.hai_env/`, workspace agents, configuration, profiles,
credentials, Activity records, product specifications and transcripts. Package
verification must use the exact committed source; the source identity, archive
digest and actual package checks are recorded separately after the commit. These
notes neither claim those future results nor authorize tags, pushes, remote drafts
or public publication.
