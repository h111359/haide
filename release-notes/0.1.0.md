# HAI 0.1.0

The first packaged prototype of HAI, a framework for AI-assisted development.
The bundle is experimental; this release establishes the starting public package
version rather than claiming stable `1.x` compatibility or a prior release history.

## Included capabilities

- Shared leader orchestration and registered specialists for environment setup,
  agent-definition management, request management, specification management,
  session chronicles, and Git/GitHub operations.
- Workspace configuration separated from the reusable `.hai/` framework, with
  optional features and independently enabled Git/GitHub integrations.
- Agent `SKILL.md` definitions and catalogues, generic specialist model/effort
  declarations, and installation-local model profiles with runtime availability checks.
- Specification contract declarations, explicit adoption/migration boundaries,
  structured tree validation, derived catalogue checks and read-only rendering.
- Standard-library Python helpers and fixture tests for startup validation,
  agent/catalogue validation, and specification auditing.
- Git/GitHub operation policies that preserve task authority, require fresh
  chronicle synchronization before commit-producing work, and leave pushes manual
  unless automated push is separately enabled after readiness verification.

## Compatibility and installation

| Boundary | Shipped target |
| --- | --- |
| HAI bundle | `0.1.0` |
| Current environment state format | `1` |
| Supported environment state formats | `[1]` |
| Specification compatibility | `1` |

The versioned [release manifest](../.hai/release-0.1.0.json) snapshots the owning
contract declarations. These targets are independent of HAI SemVer and do not
assert that a consumer workspace or specification has been migrated.

Follow [installation and upgrade instructions](../INSTALL.md). The ZIP contains
`.hai/`, the MIT license and required documentation. It excludes `.hai_env/`, local
workspace agents, configuration, secrets, product records and session history.

Prototype state using the retired `compatible_version` field is unsupported by
state format 1. Existing incompatible state or unmarked/incompatible specification
trees need scoped owner assessment and explicit authorization before adoption or
migration; no automatic legacy conversion is promised by this release.

## Experimental versioning policy

During `0.x`, new capabilities and breaking changes increment MINOR; compatible
fixes increment PATCH. Breaking changes will be described in release notes.
Moving to `1.0.0` requires an explicit decision that HAI is ready to offer a stable
public compatibility contract. Contract/state versions remain independently governed.

## Known limits

- HAI's instructions require a capable host AI environment. Model mappings, agent
  spawning, connectors, authentication and tool permissions are installation-specific.
- Mechanical validation is not proof of semantic correctness, product implementation
  or migration approval. Helpers document supported syntax and manual-review limits.
- Release preparation was verified on Linux with Python 3.12.3. Windows and
  macOS are intended targets but have not been executed for this release; OS-specific
  skipped tests do not establish cross-platform verification.
- The package has no automatic installer, upgrade runner or newly configured GitHub
  Actions release workflow. This first candidate uses local preparation; pushing and
  public publication remain separate authorized steps.
