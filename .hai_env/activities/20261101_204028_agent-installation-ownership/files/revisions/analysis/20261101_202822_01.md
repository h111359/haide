# Agent layout and workspace delivery

Revised 2026-11-01T19:55:41Z by Activity-manager from the user's clarified deployment requirement and Leader's proposed interpretation. The [previous analysis](files/revisions/analysis/20261101_195541_01.md) is preserved exactly.

## Settled deployment constraint

A new workspace initially receives only a self-contained `.hai/`. Its startup instructions and bundled core agents initialize `.hai_env/`. Optional agents can later be downloaded individually and installed in `.hai_env/agents/`. The entire `hai_agents_library/` is neither copied into a new workspace nor required at runtime.

## Revised recommendation — proposal

The current architecture broadly fits that lifecycle:

| Location | Role |
| --- | --- |
| `.hai/agents/` | Bundled core agents available for reliable first-chat startup and environment initialization. |
| `.hai_env/agents/` | Optional installed extensions and workspace-local agents. |
| `hai_agents_library/` | Reusable optional-package sources in this development/distribution repository; users acquire selected packages. |

Retain the core-bootstrap versus installed-extension boundary. Explain these delivery roles more clearly in names and documentation where needed, while keeping the shared agent format and configuration contract consistent across both runtime locations. Source-library membership does not grant execution permission; runtime registration remains required.

The earlier recommendation to unify all reusable sources first, and potentially all runtime locations later, is superseded by this recommendation in light of the deployment requirement. Those options remain in the preserved earlier analysis; they are not implementation decisions.

No rename, move, framework change or implementation plan is authorized. The user settled the deployment lifecycle; the documentation-focused recommendation above is still an assistant proposal. Analysis is complete for this discussion update; implementation remains unstarted.

## Open choice: installing the first optional agent

The three-agent `.hai/` core therefore supports a manual first optional installation.

If entirely chat-driven installation is desired, the design would need to bundle Agent-definition-manager with core or provide a narrowly scoped bootstrap installer. The user has not required that automation; this is an open design choice, not a defect or agreed requirement.
